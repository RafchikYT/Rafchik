# Rafchik — WhatsApp-бот для приёма заказов

Бот для магазина: клиент пишет в WhatsApp, видит каталог, оформляет заказ
(товар → количество → подтверждение), а готовый заказ автоматически
пересылается владельцу. Плюс авто-ответы на частые вопросы (адрес, часы работы).

Работает через неофициальную библиотеку [whatsapp-web.js](https://wwebjs.dev/)
(тот же принцип, что и WhatsApp Web — сканируете QR-код своим телефоном).
Подходит для теста/MVP на одном магазине. Для продакшена с высокой нагрузкой
или юр. лицом лучше переходить на официальный WhatsApp Business API.

## Установка

```bash
npm install
cp .env.example .env
```

Заполните `.env`:

- `OWNER_NUMBER` — номер владельца магазина в формате `<код страны><номер>@c.us`,
  например `79991234567@c.us`. На этот номер будут приходить уведомления о заказах.
- `SHOP_NAME`, `SHOP_ADDRESS`, `SHOP_HOURS` — используются в приветствии и авто-ответах.

Отредактируйте каталог товаров в `data/catalog.json`.

## Запуск

```bash
npm start
```

При первом запуске в терминале появится QR-код — отсканируйте его в приложении
WhatsApp на телефоне владельца/магазина: **Настройки → Связанные устройства →
Привязать устройство**. После этого бот начнёт отвечать на входящие сообщения.

Сессия авторизации сохраняется в `.wwebjs_auth/`, повторно сканировать QR не нужно.

## Как это работает для клиента

1. Клиент пишет что угодно боту — получает каталог с ценами.
2. Отправляет номер товара из списка.
3. Указывает количество.
4. Подтверждает заказ («да»/«нет»).
5. Заказ сохраняется в `data/orders.json` и отправляется владельцу в WhatsApp.

Слово «отмена» на любом шаге сбрасывает диалог.

## Структура проекта

```
src/
  index.js      — точка входа, обработка сообщений WhatsApp
  config.js     — настройки из .env
  catalog.js    — работа с каталогом товаров
  orders.js     — сохранение заказов
  sessions.js   — состояние диалога с каждым клиентом
data/
  catalog.json  — список товаров (редактируется вручную)
  orders.json   — принятые заказы (создаётся автоматически)
```

## Рассылка NFC-визиток бизнесам Риги + Telegram-панель управления

Второй модуль в этом же проекте: ищет бизнесы в Риге, копит их в базе лидов и
рассылает им ваш заготовленный текст в WhatsApp с того же номера. Управляется
Telegram-ботом — не нужно лезть в консоль сервера.

### Как это устроено

```
src/
  app.js          — точка входа: поднимает WhatsApp-клиент, бота заказов,
                    Telegram-бота и обработчик ответов от лидов
  whatsappClient.js — создание WhatsApp-клиента (QR-код при первом запуске)
  discovery.js    — поиск бизнесов в Риге через OpenStreetMap Overpass API
  leads.js        — база лидов (data/leads.json), статусы, дедуп по телефону
  outreach.js     — шаблон сообщения, отправка, автоотправка с лимитами
  telegramBot.js  — команды управления в Telegram
data/
  outreach-message.txt — ваш текст для рассылки (редактируется вручную,
                          поддерживает {{name}} — подставится название бизнеса)
  leads.json      — база найденных бизнесов (создаётся автоматически, в git не идёт)
```

### Поиск бизнесов

Данные берутся из **OpenStreetMap** (Overpass API) — это открытые данные без
скрейпинга Google Maps и без риска банов за нарушение ToS. Минус: телефон
известен не для всех объектов на карте, поэтому находится не 100% бизнесов
города, а то подмножество, что заполнило карточку в OSM.

Доступные категории (команда `/categories` в Telegram покажет актуальный
список): `cafe`, `restaurant`, `bar`, `fastfood`, `bakery`, `hairdresser`,
`beauty`, `spa`, `dentist`, `clinic`, `gym`, `hotel`, `autoservice`,
`carwash`, `pharmacy`, `clothes`.

Центр и радиус поиска настраиваются в `.env` (`RIGA_CENTER_LAT/LON`,
`SEARCH_RADIUS_M`, по умолчанию — центр Риги, 8 км).

### Настройка Telegram-бота

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. Узнайте свой chat id через [@userinfobot](https://t.me/userinfobot).
3. Впишите в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=...
   TELEGRAM_OWNER_CHAT_ID=...
   ```
   Без `TELEGRAM_OWNER_CHAT_ID` бот будет отвечать любому, кто его найдёт —
   обязательно заполните это поле.
4. Отредактируйте `data/outreach-message.txt` — впишите свой готовый текст.
5. Запустите `npm start`, отсканируйте QR (как обычно), напишите боту `/start`.

### Команды Telegram-бота

- `/search <категория>` — найти бизнесы и добавить в базу лидов
- `/categories` — список категорий
- `/leads [статус]` — список лидов (`new`, `sent`, `replied`, `interested`, `declined`)
- `/send <id>` — отправить сообщение конкретному лиду вручную
- `/auto on` / `/auto off` — включить/выключить автоотправку по очереди `new`-лидов
- `/interested <id>` / `/decline <id>` — изменить статус вручную
- `/stats` — статистика по лидам
- `/message` — показать текущий шаблон рассылки

### Как обрабатываются ответы бизнесов

Если бизнес отвечает на WhatsApp-сообщение, ответ пересылается вам в Telegram.
Если в ответе есть слово «стоп» (или похожее) — лид автоматически помечается
`declined`, и рассылка ему больше не пойдёт.

### Важно про риски и легальность

- **Это не официальный WhatsApp Business API** — рассылка идёт через личный
  номер (`whatsapp-web.js`), как и основной бот заказов. WhatsApp запрещает
  массовые автоматические сообщения незнакомым людям в своих правилах — при
  большом объёме или жалобах номер может быть заблокирован. Поэтому:
  - `/auto on` по умолчанию шлёт с большими случайными задержками
    (`OUTREACH_MIN_DELAY_SEC`/`OUTREACH_MAX_DELAY_SEC`, по умолчанию 45–120 сек)
    и дневным лимитом (`OUTREACH_DAILY_LIMIT`, по умолчанию 30) — не отключайте
    эти лимиты полностью, увеличивайте постепенно.
  - Всегда давайте понятный способ отказаться («стоп») — это уже встроено в
    шаблон сообщения, не убирайте эту фразу.
  - Для серьёзного объёма (сотни сообщений в день) переходите на официальный
    WhatsApp Business API — так безопаснее для номера и понятнее с точки
    зрения правил площадки.
- **B2B-рассылка по WhatsApp юрлицам в ЕС/Латвии** также подпадает под общие
  нормы о нежелательных электронных коммерческих сообщениях (аналог
  ePrivacy-регулирования) — рекомендуется по крайней мере: чётко представляться,
  указывать, что это предложение, и оперативно останавливать рассылку по
  первой просьбе. Ответственность за соответствие локальному законодательству
  лежит на владельце рассылки.
